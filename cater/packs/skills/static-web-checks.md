# 静态网页行为验证

此指引适用于已提供browser_check的场景，不会因此获得任意网址、外网、登录态或后端服务权限。

## 固定输入与覆盖目标

阅读本次HTML及其本地JS/CSS等依赖，选择需要检查的实际发布事件。检查完整固定副本，不把旧版通过当作新版结论。按顾客目标挑可失败的交互断言，先想清楚初态、真实操作、可观察结果及边界条件。

## 使用实际操作

通常通过click、fill、press或click_at模拟输入，再用assert_visible、assert_text或assert_js检查实际页面。plan需包含entrypoint和steps，每步带action、简短label及该动作要求的字段，至少一条assert_*；文件清单由宿主从artifact_seqs建立。

evaluate只用于必要的页面内准备，不能先把结果变量改成正确值，再宣布功能通过。不要用恒真断言、期望标签或打开页面代替验证。canvas/游戏还应验证状态或像素确实变化，截图本身不证明游戏规则正确。

## 核对回执再交接

读取outcome、具体步骤、实际观测、页面错误、退出码、文件版本及scope_current。status=ok只表示取得回执。区分断言失败、工具不可用、超时和历史范围；未知调用先核对，不以重跑掩盖未知。

发现问题就说明依据并修正实现或有误的检查，再对新版本实际执行；按需交回复核。通过时也交代覆盖范围和未验证部分，不将少量断言升级成全部业务或所有平台正确。
