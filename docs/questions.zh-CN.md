# 在对话中追问交付

在已有对话上方选择问号图标，继续用原聊天框提问，例如“为什么选这个方案，换一种方案会影响什么？”或“我应该怎样自己复查？”可以 `@` 一位已配置的伙伴。取消提问可回到原协作草稿，各类草稿分别保留。

提问不会改任务目标、工作计划或验收结论，也不会重做已经完成的工作。伙伴应结合具体成果解释，指出结论依据、推测和未检查的范围。回答中的原文引用、版本与限制可展开查看；任务之后更新时，旧回答标为历史版本。

目前只精确识别少量直接查询（如“为什么这么改？”）和“请讲解：…”前缀。自由追问使用问号入口；混合了新要求的普通消息仍按方向变更处理。当前工作台仍是一项任务对应一个对话，尚未实现长期群聊承接多项独立工作的消息归属与语义路由，不能据此认为任意消息都会自动正确分类。

## 模型与记录

提问对象需要可用的模型通道；默认是店长，也可点名其他伙伴。演示模式不会编造针对性讲解。证据不足时允许明确无法判断；模型回答不得直接发布成果、修改要求或替代任务验收。

讲解使用单独队列，不覆盖协作的后续执行安排。模型用量纳入原有统计与通道预算；调用失败或中断后不自动重放。需要进一步询问时，可以在同一群里继续发出一个新问题。

提问保存来源事件引用，按提问时的记录读取；仅带上最近四轮仍有效的问答作交流背景，旧回答不会升级为事实证据。返工后的旧提交、旧验收和被替换的检查回执不进入新问题的依据。阶段验收和检查状态更新后，旧回答标记为历史版本；提问后适用店规变化则停止调用，要求重新提问，避免混用版本。单次输入超过当前容量时明确停止，不静默截断要求或正文。当前尚无大历史的分段检索。

## API

`POST /api/tasks/{task_id}/questions` 接收：

```json
{
  "question": "这个方案的取舍是什么，怎样自行判断是否合适？",
  "request_id": "question-request-20261015",
  "role_id": "dev"
}
```

`role_id` 可省略。创建与重试均返回 `202` 和标准任务详情，附带 `questions`。同一次发送失败重试时保持请求标识与内容不变；重复请求不会再创建问题或重放已启动的模型调用。更换问题、对象或群聊时复用标识会返回 `409`。服务器生成依据与版本，不接受客户端注入。

讲解的引用检查只证明引文与原始记录相符，不证明解释的因果推断一定正确，更不证明顾客已理解。真实模型的讲解质量仍需实际任务评测。第三方 CLI 内部工具、磁盘缓存与网络权限仍是其信任边界，讲解合同不构成通用主机沙箱。
