# 桌面执行权限与沙箱设计

状态：沙箱及细粒度网络/密钥隔离仍为设计提案；已实现预配置工作目录的只读、编辑、宿主执行三种绑定，见[实际工作区工具](workspaces.zh-CN.md)。不能把本页中的其余目标能力当作已可用功能。

## 当前事实

- Web 是本地运行时的聊天界面，浏览器本身不因使用电脑就获得文件、命令或管理员权限。
- 配置的 CLI driver 及 `cater verify` 是主机进程，通常拥有启动它们的用户的文件和网络权限。两者都在允许目标启动前建立进程组或 Windows Job，超时后清理管理范围内的进程；这些措施与输出上限控制生命周期，不隔离文件或网络访问。
- Codex 示例适配器固定使用供应商的 `read-only` 沙箱，不开放写入或跳过沙箱参数；这个边界只适用于该适配器，不适用于所有 driver。
- 网页可选择可信配置中的工作区和权限，不能创建任意目录授权或增加程序；execute 模式的解释器和脚本仍拥有宿主权限，尚无 OS 沙箱。

## 产品目标

电脑端作为主要工作台：组织代码、文档、PPT 等任务，指定工作区，检查变更、构建、依赖与成果。手机作为同一任务的伴随入口：聊天、修改目标、看进展和下载成果。手机发来的请求也应通过同一服务端权限检查，不能因为入口不同绕开策略。

“部分/全部权限”应表达为明确的执行配置，而不是模糊的二选一：

| 配置 | 允许的范围 | 必须说明的限制 |
| --- | --- | --- |
| 只读分析 | 指定工作区读取；指定模型调用 | 不改文件、不安装依赖，不意味着其他任意进程被隔离 |
| 工作区执行（默认目标） | 指定工作区写入、构建、测试；授权的依赖源 | 禁止访问未挂载的主机路径、私有密钥与系统设置；网络和密钥单独授权 |
| 主机信任模式 | 用户明确授权范围内的主机执行 | 无法称为安全沙箱；不等于管理员权限，不默认允许发布、删除数据、修改账号或传输凭据 |

项目级授权可以覆盖重复的正常构建与测试，避免每次问顾客；高影响操作仍独立授权。角色只能申请能力，不能自行扩大自己的权限。

## 执行边界

1. 服务端绑定任务、工作区、权限版本、执行后端与能力配置，前端不能提交任意参数覆盖这些绑定。
2. 所有真实工具动作经过同一网关检查；不能只限制 Cater 工具，却允许 driver 自己启动任意主机命令来绕过。
3. 沙箱后端按实际支持范围执行隔离，并在启动失败或不支持时拒绝执行，不能静默退回主机。
4. 文件挂载、可写目录、网络、进程资源和密钥分别控制。独立工作目录、路径前缀检查或提示词都不能单独证明文件隔离。
5. 依赖下载需要显式网络范围、缓存和资源限额；安装脚本属于可执行代码，不是无风险下载。
6. 审计记录后端、策略版本、动作与结果，不记录密钥。权限调整在后续动作生效；运行中的动作需要取消/隔离销毁策略，不能假装可即时收回已泄露的权限。

## 后端选择与验证

优先复用供应商可验证的工作区沙箱，或独立容器/虚拟机后端，不自行把 subprocess 包装成安全沙箱。保持 Python 核心零第三方依赖；执行环境可以是可选系统组件，未安装时明确不可用。

- Docker Rootless 降低以 root 运行守护进程与容器的风险，但不自动保护用户已挂载的主机文件。绑定挂载默认可写，范围和只读标记必须由可信服务端决定，不能开放 Docker socket 或任意挂载参数给 Agent。[Rootless 文档](https://docs.docker.com/engine/security/rootless/)、[绑定挂载文档](https://docs.docker.com/engine/storage/bind-mounts/)
- Windows Sandbox 支持网络开关和映射目录的只读配置，但采用前还要验证无人值守调用、结果回传、生命周期与并发是否适合 Cater，不能仅凭它叫 Sandbox 就接入。[官方配置文档](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)

进入权限 UI 实现前，需完成真实后端契约测试：越界路径/链接、未授权写入与联网、权限降级、后端失效、子进程、凭据泄露、安装脚本和审计关联。UI 应展示实际生效的范围及未隔离项，而非只显示“安全”。
