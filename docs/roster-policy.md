# 默认编队准则

Cater 的默认猫咖不是按职位数量堆叠，而是按决策覆盖和可交付边界配置。

## 当前编队

- 店长：唯一入口、任务理解、路线选择和最后的自治收束。
- 铲屎官：白露负责需求与产品判断，阿程负责工程边界与可靠性，知夏负责质量与风险。三席能形成有意义的交叉检查，又不会把普通任务变成例会。
- 猫咪：月亮负责目标与用户价值，罐头负责交互与视觉，米寇负责工程实现，三角负责验证与风险。

## 协作边界

默认分解顺序是：月亮先明确价值与验收，罐头和米寇基于这个边界并行推进交互与实现，三角在前序成果基础上检查风险与证据。店长会把这次选中的猫咪写入任务计划：纯说明和范围澄清通常先交给月亮；视觉或交互问题会加入罐头；实现、验收和风险信号再分别加入米寇、三角。内阁明确分发或复杂任务则保留完整编队。店长不应为了凑齐角色而让所有猫咪发言。

## 何时扩容

新增铲屎官前，先确认现有三席是否已经无法覆盖一种独立且高风险的判断，例如合规或安全。新增猫咪前，先在真实任务中反复观察到一种稳定的交付物既不属于目标、交互、实现、验证，也无法由其中一只猫以明确边界承担。

每个新席位必须同时具备：清楚的 charter、可观察的输入输出、与其他席位不同的失败模式，以及可以由角色卡配置的 driver。否则它只会增加 token、延迟和对话噪音。
