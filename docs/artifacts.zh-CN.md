# 可读成果合同

伙伴的聊天发言用于交流进展，`deliverables` 用于发布可以阅读和带走的成果。标题和摘要仍是必填字段；旧的摘要与资源引用继续兼容。

```json
{
  "deliverables": [
    {
      "title": "消息重复发送的排查说明",
      "summary": "记录复现方式、调用影响和下一步验证。",
      "kind": "report",
      "content": "# 排查说明\n\n## 观察\n同一消息出现两次。\n\n## 待排除\n需要区分重复提交与重复消费。\n",
      "format": "markdown",
      "filename": "排查说明.md"
    }
  ]
}
```

## 正文与边界

- `format` 支持 `markdown`、`text` 和 `code`，未提供时按纯文本处理。
- 正文保留原始缩进和换行，每项最多 65,536 个 UTF-8 字节，每次贡献最多八项。
- 超大正文或不支持的格式会留下 `content_error`，保留摘要并省略正文；不会截断代码后假装交付完整。
- `filename` 是文件名，不是任意写入路径。路径分隔符、控制字符和 Windows 设备名不会被采用；模型不能指定宿主目标目录。
- `uri` 仍是资源引用。Cater 不因收到路径就访问本地文件，也不把引用当作文件存在的证据。
- 正文会持久化到只追加事件链。发布者应只提交任务需要的可见成果，避免把密钥、密码或私有工具日志写进正文。

修正小问题时，执行者也可以返回 `artifact_edits`，包含输入成果的 `artifact_seq`、唯一匹配的 `old_text` 和替换后的 `new_text`。宿主绑定原始正文摘要，只对本次收到的输入或自己的上次成果应用精确替换，生成完整新文件，再实际检查和独立复核。可选的 `expected_sha256` 若提供则必须匹配；原文或摘要不匹配时不猜测位置。这个方式只修改内联成果，不授予文件系统或命令执行权限。

修订自己的多文件成果时，未改动的文件也会进入新的完整快照，不因只修改一个文件而丢失其余文件。宿主记录修订来源；检查与最终打包只采用有来源依据的新版，审计仍保留原件。不同分支的同名文件不会被无依据地覆盖，完整快照超过八项时整体拒绝，不静默截断。

阶段复核以判断和理由为主，整体复核补充交接说明；宿主绑定实际输入版本与检查回执，不要求模型逐项抄写引文。语义判断仍可能出错，检查通过也只代表实际执行的覆盖范围。

运行时增加正文的字节数和 SHA-256 摘要，并记录来源。内置演示 driver 发布 `local_demo`，其他 driver 发布 `external`；界面对应“演示样例”和“成员发布”。来源不能由模型自行声明，发布也不代表独立验证通过。

## 如何取回

使用磁盘数据库运行时，有效的工作提交会自动保存到数据库同级的 `artifacts/` 专用目录，按任务和提交摘要隔离版本。文件与清单先写入暂存目录，校验后整体发布；不覆盖已有版本，不运行生成代码。内存数据库不会写文件。新一轮执行也会为当前已提交成果补存；可信本地调用可使用 `Runtime.persist_artifacts(task_id)` 单独补存，不调用模型或改变验收。

界面的“已保存到本机”只来自与提交、正文摘要匹配的宿主回执，展开可复制真实路径。这里的本机指运行 Cater 的电脑，远程访问者仍需下载。磁盘失败保留事件链中的原文，明确显示保存失败；后续重试会核验原有文件，检测到篡改不静默覆盖。保存记录说明写入时状态，不保证文件永远未被外部进程改动，也不代表通过验收或已经启动网站。

聊天成果消息和成果板均提供“查看正文”和下载图标。阅读器也支持复制和下载，关闭后回到原入口；HTML 和代码不会在工作台内执行，外部图片不会自动加载。HTTP/HTTPS 来源需要用户显式打开，本地路径保持为引用文本。

工程 ZIP 的文件清单支持逐份打开不超过 64 KiB 的 UTF-8 文本，直接阅读 README 和源码，无需先下载整包。阅读器显示所属 ZIP、发布序号及成员路径，核对保存快照的字节数与 SHA-256；读取不访问当前工作目录、不执行文件、不调用模型。空文件如实显示；二进制仅显示元数据，超限文件仍可通过整包下载取得。预览的是该次发布，不代表最新磁盘状态、独立发布或验收通过。

较长摘要默认显示短预览，展开“完整摘要”可读原始全文；预览中的空白会合并，全文的换行不变。阅读器同样控制摘要高度，为正文保留空间，复制和下载仍取完整正文。标题与文件名相同时不重复显示；不能直接打开的内部引用在“资源引用”中展开，不变成链接或运行入口。

单份正文发布后即可查阅或下载，不必等待整体验收。下载的是该条消息的成果，不代表当前工程已启动或验证通过；正式交付包仍需完成版本绑定验收。对单文件 HTML，可在审阅源码后打开已保存文件，或下载到其他设备后打开；含外部依赖的工程应以实际运行说明为准。

## 原生对话的文件版本

原生消息协作的成果板默认展示本轮每个文件名的最新发布，明确标记尚未确认交付；同名旧稿收进默认折叠的“历史发布”。历史可以继续打开正文或单独下载，不删除原始事件。新目标还没有发布文件时，不把旧目标文件当作本轮新成果。

有至少两份完整的同名文本时，成果板提供“对照已发布版本”入口。选择文件和明确的旧、新发布序号，可查看发布者、记录指纹、换行信息和逐行差异；默认新版沿用成果板当前展示的文件，冻结交付不会被后来发布替换。比较不改变交付清单、复核结论或文件，也不会调用模型。目标记录缺失或不同时不自动猜比较基线，跨目标需手动选择。同名和文本差异不证明返修关系，更不能说明改动理由或业务正确性。

逐行差异采用 [jsdiff](https://github.com/kpdecker/jsdiff)，保留空白、大小写和换行差别，不渲染或执行正文里的HTML/代码。其许可证随网页资源发布，在对照窗口末尾的“差异组件许可”中可读。字节数不符合记录、缺失/报错正文或归档不参与文本比较。计算有行数、编辑距离和时间预算，超限会明确说明没有完整逐行结果，并保留两版完整原文；不会截断后显示“无改动”。切换对话、目标或访问凭据会关闭旧比较窗口。文件内容相同仅说明已收到的正文相同，发布记录指纹的展示不等于浏览器重新核验字节。

店长确认交付后，成果板按该次完成记录锁定文件事件及内容摘要，不按“最后出现的同名文件”替换。交付后发布的版本另行折叠，不混入原包。店长的默认清单只收本轮目标内最新文件；需要沿用已有依赖或明确筛选文件时，可用 `finish_work.artifact_seqs` 选择本群所需版本，并记录沿用范围。明确空清单表示这次没有文件交付。

本轮已有复核通过的成果，但本次选择一份都没有包含时，宿主会返回这些获批版本供店长核对，不自动附文件，也不要求顾客审批。确实有意不附时，可填写 `omitted_approved_artifacts_reason`（非空，至多1000字符）；原因与交付一起保存，可在原交付详情和 `read_delivery` 中读取，有其他附件时也包含在下载包的交付说明中；无附件不会生成空下载包。纯文字结果及未获批草稿的空选择不新增此要求。理由不豁免版本、待复核、未结束工作或未知操作检查，也不证明自然语言目标已经满足。仅选部分获批成果仍允许，不表示所有所需文件都已齐全。不要为消除提示盲目删除 `artifact_seqs`，默认选择可能收录本轮的其他草稿。

文件清单缺失、引用无法对应、正文不完整或旧目标文件没有明确沿用记录时，界面只展示已发布版本并提示待核对，不把候选稿改称最终文件。历史旧记录仍可查阅，不能因为兼容下载入口存在就认定属于当前目标。

已完成目标的交付保持冻结。重复 `finish_work` 只有与原成功请求等价时才确认未发生变更；不同文件选择或说明不会返回补交成功，店长应读取原交付，按顾客意图选择普通答复或采用新的工作目标后交付。旧记录不会被覆盖，也不因补交而强制重做未改动的源码、开会或新增顾客审批。

`finish_work` 成功后，该成员本轮让出执行，同批后续工具不再调用。必要的读取与核对应在交付前完成，交付后的追问仍可正常读取原说明和答复，不会因此重写原记录。

成果板的整包按钮会请求 `GET /api/tasks/<task_id>/delivery?delivery_seq=<完成事件序号>`，下载绑定当前看到的交付，正文重新计算 SHA-256；版本已变化则返回409，不退回另一份包。这个参数仅适用于原生协作；旧无参接口保持兼容。文件清单与ZIP在同一读快照内生成，之后先释放数据库快照再发送网络响应。切换对话、收到更新目标或改变访问凭据会取消尚未完成的旧下载；失败不自动重试。

`GET /api/tasks/<task_id>` 和事件导出包含完整正文；`GET /api/tasks` 只返回成果摘要与元数据，降低列表加载成本。组织共享记忆继续只传有界摘要，避免把大段代码自动重复塞进每次模型调用。

模型侧的紧凑成果索引保留发布者 `actor`、来源和字节数；同名多次发布只默认发送最新版及 `versions_total`，不是把旧版正文自动塞回上下文。需要明确比较基线时，可用已有 `read_artifact`，带本群一份成果的 `artifact_seq` 和 `section: "versions"`，按其确切文件名读取本群历史发布元数据，`after_seq`/`limit` 分页（默认20、最多50）；`next_seq` 用作下一页的 `after_seq`。目录不含正文、摘要或本机路径，默认正文及ZIP读取方式不变；目录分页不能与 `path`/`offset`/`length` 混用。

读取普通文本成果时，`content_metrics` 由宿主重新统计该确切版本的完整保存原文，提供 UTF-8 字节数、Unicode 码点数、非空白码点数和 CJK 表意文字数。计量包含 Markdown 标题、标记和空白；正文分页时仍统计完整原文，不是当前节选，也不是渲染后的正文字数、英文词数或模型 token 数。模型自报的同名字段不能覆盖这些观测，不写回发布记录。历史正文无法按 UTF-8 计量时不编造零值；版本目录、ZIP 清单和本组的 ZIP 成员读取不返回推测计量。计数本身不决定“约200字”的含义、验收阈值或是否通过，仍须明确范围与口径。

历史目录保留旧目标和相同字节的不同发布事件，不推断父子、返修关系或验收沿用。`actor` 是发布者，不证明谁实际编辑；没有新版发布也不证明没有改磁盘文件。讲解改动应先明确比较的确切旧、新版本，再按需要读取正文和实际操作回执；保存的交付说明仍是成员自述，不能替代这些事实。

随附 Codex CLI adapter 的输出 schema 已包含正文字段，同时接受既有摘要合同。API/其他 CLI driver 可以直接返回同一结构，无需给 Python 核心增加依赖。
