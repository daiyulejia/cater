# 当前执行能力

Cater 的模型接入与工程执行能力分开提供。当前版本的 API 通道用于文本理解、规划、产出和复核；连接 API 不会自动获得本机文件或终端权限。

| 能力 | 当前状态 |
| --- | --- |
| 中文聊天、点名、任务内语义分流 | 已接入；语义分流需要配置店长模型 |
| 工作项、依赖与阶段/整体验收 | 已接入版本与证据校验；判断质量仍需实际任务验证 |
| 文件成果 | 可阅读、复制、下载内联正文；不按模型路径自动写入工程 |
| 打包 | 可下载验收后的正文 ZIP、清单和交接说明；不会自动构建项目安装包 |
| 浏览器检查 | 可选 Playwright 执行器检查已提交静态 HTML，保存实际回执 |
| 本机命令检查 | 可信本地调用者显式使用 `cater verify`，并非模型已有任意命令工具 |
| CLI 接入 | 长驻 NDJSON 外部驱动；实际工具和权限取决于该驱动，随附 Codex 示例固定只读 |
| 本地工程读取、搜索、补丁、建目录 | 尚无通用模型工具接口；保存事件和临时副本不代表工程编辑能力 |
| 构建、依赖安装、服务和日志管理 | 尚未形成通用自动执行链 |
| Git 分支、提交、推送、PR/MR | 尚无 Cater 原生执行流程；检查中的 Git 状态记录不等于版本管理工具 |
| MCP 与通用 Skill | 尚无通用发现/调用系统；当前浏览器指引只在检查时加载 |
| Android、iOS、桌面、Office 工具链 | 尚未接入对应平台构建、设备测试或文档渲染节点 |
| 文件/网络权限沙箱 | 尚无通用实现；进程组、Windows Job、独立目录不等于权限隔离 |
| 长期群聊、多任务归属 | 有独立后端接口，现有网页仍以一项任务为当前对话 |

任意外部 CLI 可以自行提供更多能力，但必须核实其实际权限与副作用恢复契约，不能沿用纯文本调用的无工具假设。角色名称、职责与店规不授予主机权限。

模型返回的单个 JSON 对象允许完整 Markdown JSON 围栏或一个末尾围栏；内容仍须通过原有字段、来源、版本与权限检查。多对象、前后解释文字、重复字段和不完整 JSON 不会被拼接成可执行建议。解析失败会保留当前任务并显示原因，不代表成员没有做过工作，也不代表任务已完成。

当前恢复能力仍有边界：有副作用的未知结果不能盲重放；阶段检查也不能代替整体行为验收。代码存在和回归通过不能证明复杂长任务始终正确。

详见[浏览器检查](browser-checks.zh-CN.md)、[本机验证](local-verification.zh-CN.md)、[工作项与验收](work-items.zh-CN.md)及[执行权限设计](execution-permissions.zh-CN.md)。
