# 本机检查的含义和运行边界

静态网页也可以启用 [自动浏览器检查](browser-checks.zh-CN.md)。下文的 `verify` 是受信任操作者显式运行本机命令的入口，与模型能访问的有限浏览器动作不同。

`cater verify` 记录你显式指定的命令在本机的运行结果。Agent 提交的诊断、交接说明和测试声明仍然属于成员报告；关联 `--for-event` 方便追查，但不会自动将报告改成已证实结论。

```powershell
cater verify <任务ID> --cwd . --timeout 60 -- python -m unittest discover -s tests
```

## 命令与子进程

检查进程先等待启动许可。父进程建立 Windows Job 或 POSIX 进程组后，才传入命令，避免命令在管理边界建立前派生子进程。命令标准输入关闭，适合无需人工输入的测试、构建和静态检查。

命令结束、超时或调用被中断时，Cater 会清理管理范围内仍然运行的派生进程。因此不要用 `verify` 启动需要长期保留的服务。超时计算包含执行进程启动时间；之后还会进行有限时间的输出收尾和 Git 元数据采集。

输出读取也有收尾期限。没有读到完整输出时，事件会记录 `complete: false` 和清理错误；即使命令退出码为零，也不会显示命令通过。输出摘要只对应实际读取到的字节。

这是进程生命周期管理，命令仍然拥有当前用户的文件和网络权限。POSIX 上主动创建新会话的程序可能脱离进程组；Cater 会限制输出等待时间，但不能靠进程组提供权限沙箱。

## 证据与隐私

- 默认事件只保存输出字节数和 SHA-256 摘要，终端会显示受限的输出预览。
- `--record-output` 允许保存每个输出流最多 8 KiB 的 UTF-8 摘录。长输出分别保存开头和末尾，各最多 4 KiB；`preview_mode=head_tail` 的 `excerpt` 与 `tail_excerpt` 不是连续全文，中间未保存。采集尚未结束时，末尾仅指已经采集到的最后一段。无效 UTF-8 用替换字符显示，正文不是原始字节副本；字节数和 SHA-256 仍对应实际采集的原始输出。
- `complete=true` 只说明流采集结束，不表示预览未省略，也不代表任务验收通过。没有开启 `--record-output` 时，事件不保存任一段正文；命令行终端沿用受限的开头预览。
- 命令参数和工作目录会进入事件链；密钥等敏感值应通过环境或受保护文件传入。
- Git 状态是检查结束时的提交号和脏工作区标记，没有绑定未提交文件的完整内容。
- 退出码为零只说明该命令成功。根因判断是否成立、调用方是否被影响、哪些场景未覆盖，仍需要相应的复现和回归证据。

实现依据：[Windows Job Objects](https://learn.microsoft.com/zh-cn/windows/win32/procthread/job-objects) 和 [Python subprocess](https://docs.python.org/3/library/subprocess.html)。
