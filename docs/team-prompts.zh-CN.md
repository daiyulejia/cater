# 团队提示分层

团队运行说明由 `cater/team_instructions.py` 组装，不用顾客文本关键词选择流程。

| 层次 | 选择依据 | 内容 |
| --- | --- | --- |
| 共享底线 | 始终保留 | 唯一身份、语义理解、顾客范围、事实与权限、实际交接、版本复核及返修闭环、自然中文说明 |
| 角色职责 | 配置中的店长 ID | 店长负责整体对接和最终交付；伙伴负责具体委托与交回，不由名字猜职位 |
| 状态说明 | 本轮结构化上下文 | 非空冻结背景、活委托、派出工作、知会、检查点、恢复/接续、问卷答复、未知操作、历史交付、历史读取与工具历史节选 |
| 客户端边界 | 外部执行通道 | 临时启动目录不是顾客工程，工具交接成功后让出执行机会 |

原生通道每轮重新选择状态说明；外部通道首次发送同一套共享与状态说明，再附客户端边界。外部执行期间仍以工具回执获取新情况，不额外发模型请求。复核版本、返修闭环、未知结果不重放等约束始终常驻，因为外部运行可能在首次输入之后才创建复核或派出工作。

工具参数、分页和成果发布方式以现有 schema 为准，不在常驻说明重复完整指南。Skill/MCP 指引仍按需读取，不是工作前置条件。状态说明不复制消息、成果或回执正文；没有改变上下文投影、持久事件、工具集合、权限、调度及验收实现。

## 协作与版本复核

`delegate` 不带 `review` 时仍是普通工作、讨论或咨询。伙伴读过文件并回报意见是有用的检查证据，但不会自动登记为该版本的正式批准。

需要独立验收成果时，作者（也可以是店长）先保存候选版本：文本用 `publish_artifact`，工作目录里的文件用 `publish_workspace_file`，工程文件集合用 `publish_workspace_archive`。这些工具返回 `artifact_seq`；保存候选版本不是最终交付。作者用 `request_review` 提交该序号，该工具本身会派发复核；复核者读取对应版本后用 `record_review` 记录结论。返修仍使用原复核链，最终由店长 `finish_work` 选择获批版本。

也可以一次交接：`delegate` 明确带上 `review.workspace_file`（相对 `path` 和 `format`），宿主保存该单份UTF-8文件的完整候选并创建正式复核，成功后本轮等待；`review.artifact_seqs` 则选择已有版本。`request_review` 同样支持 `workspace_file` 或 `artifact_seqs` 二选一，修订仍填原 `review_seq`。文件上限沿用文本成果的64KiB；工程集合先发布ZIP再提交序号。未读全、目录范围变化或请求被拒时，不提交部分候选或半份复核。

文件快照在事件事务外取得，候选、正式请求和完成回执在同一事件事务提交；此快捷入口只保存数据库中的不可变正文，不写回工作目录，也不在事务里物化另一个文件。下载仍来自确切已选版本。这不是通过指令关键词猜测复核意图，只有模型明确填写 `review` 才转为复核。

这一区分不要求所有工作都复核，不按顾客措辞自动插入流程，也不把普通咨询强制转换成验收。工具说明只澄清已有能力，不新增调度、权限或交付拦截。模型是否能在普通任务里正确选用工具，仍须真实运行验证，不能由说明文字或单元测试推定。

共享说明提供一个不限定任务领域的操作例子：交付文件检查可直接用带 `review.workspace_file` 的交接，伙伴读取该版本并记录结论，反馈沿原链修订。讨论方法仍是普通委托。例子帮助模型理解操作，不把顾客某个词映射为固定流程。

对客交付按信息量展开：简单成果给简短结果和文件入口，长说明与依据按需放入 `handoff`，不在主摘要和折叠细节重复全文或检查清单。这是表达指引，不删除依据、限制输出或省略必要的运行与边界说明；是否更清楚、更快仍需实际任务检验。

## 切换目标的回执

外部模型在一次运行开始时取得上下文，调用工具后不会重新发送整份初始 prompt。`set_objective` 因此在原有 `status`、`goal` 之外，返回本次采用的 `revision`、`work_status` 与 `scope_changed`。真正采用新目标时再附一条宿主 `continuation_note`，说明这些值更新旧快照，旧目标的完成状态和批准不适用于新目标，并给出按需协作的续接提示。

同一个仍在进行的目标不生成新版本、不重复提示；已经完成后明确再次采用，即使目标文字相同，仍沿用既有行为生成新版本。此回执不清空历史、不重启模型会话、不改变权限、验收或目标采用条件，也不会根据顾客关键词替模型选择是否换目标。模型是否采纳新状态，仍需实际核对。

复核返修链属于创建时的目标版本。仍在同一目标内修订时沿原 `review_seq`；已经采用新目标、原复核显示 `stale` 时，旧记录只作历史参考。成果作者如需对当前目标提交复核，应省略旧编号、选择本次待验版本；宿主不会自动重开复核或把旧批准改签给新目标。失效编号的报错会解释这个区别，不仅让伙伴反复查找不存在的当前替代编号。

## 外部会话连续性

外部客户端的一次模型交互可能执行很多工具调用，不把这些调用数当成原生通道的模型轮数。外部会话不会仅因为累计32次工具调用就强制重开上下文；原生通道的模型轮次边界不变。外部客户端原有的失联检测、总运行时限、明确交接后的撤权，以及顾客新消息、暂停、目标/权限变化与未知副作用检查继续生效。达到配置的真实时间预算仍需先结算进程与回执，再按已确认检查点处理，不盲目重放。

## 大小与边界

以身份“店长”、ID `leader` 为固定比较输入，基线为提交 `d1a09db` 的提示常量；下表均为实际编码后的 **UTF-8 字节**，不含上下文 JSON、工具 schema、工具历史或客户端自带提示。

| 场景 | 原生说明 | 外部说明 |
| --- | ---: | ---: |
| 修改前，每次固定说明 | 11,853 | 12,429 |
| 当前，无可选状态 | 4,312 | 4,672 |
| 带原委托与未关闭工作 | 4,699 | 5,059 |
| 原委托、正常分段恢复、未知操作 | 5,073 | 5,433 |
| 已有交付与历史文件读取 | 4,720 | 5,080 |

`team.model_called.request_sizes` 仍分别记录实际说明、上下文和完整 prompt 的字节数。测试覆盖原生与外部首次说明一致、每轮状态更新、顾客关键词不触发说明、消息正文保真、回执计量及两轮返修后的确切版本交付。

字节减少不等于 token、费用或耗时按比例下降，也不证明模型更可靠。角色行为、是否漏掉必要验证、是否过度复核、解释是否失实，仍需真实模型跨任务验证。不能为了压缩数字删除未关闭工作、原始要求或版本证据；本次未裁剪这些数据。
