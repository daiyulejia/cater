# 长期群聊接口（开发中）

目前提供群消息与任务归属的后端接口。**现有网页还未切换到这些接口，普通网页输入仍使用原任务命令入口。** 模型自动理解消息、回答群内讨论、采用任务要求和自动调度尚未接入此路径。不要把“消息已保存”当成“伙伴已收到执行任务”。

一个群可以没有任务，也可以关联多个任务。群消息原文单独保存；引用某项任务或回复某条记录，不会自动修改任务目标、使验收失效或启动执行。

## 创建与发送

`POST /api/rooms`：

```json
{"title":"一起做作品集","request_id":"create-room-20261015"}
```

返回 `room` 与 `created`，其中 `room.id` 用于后续请求。

`POST /api/rooms/{room_id}/messages`：

```json
{"text":"先聊聊首页怎么做，不急着执行。","request_id":"message-20261015-001"}
```

返回 `message`（事件，包括 `id` 与 `seq`）及 `created`。可附带 `task_id` 表示引用本群任务，或 `reply_to` 表示本群消息/任务记录的事件序号。不同群的引用会被拒绝；明确指定的任务不能与回复对象指向不同任务。

同一发送重试应保持 `request_id` 和内容不变。相同请求返回原消息；更换内容或引用返回 409。同一个发送标识可以在不同群独立使用。群创建请求标识在工作台内去重。

## 明确创建工作

`POST /api/rooms/{room_id}/tasks`：

```json
{
  "message_id":"上一步返回的消息 id",
  "goal":"完成作品集首页草稿",
  "acceptance":["包含项目展示与联系方式"],
  "request_id":"start-task-20261015-001"
}
```

可显式指定已有 `project_id`。返回 `task_id` 和 `created`。消息必须来自本群顾客；创建目标可以是整理后的需求，不要求原话照抄。

这是独立的创建操作，不是每次聊天必填的表单要求。后续自然路由将使用同一数据边界，但本接口当前不做语义推断。任务创建与群归属在一个事务中保存；中途失败不会留下半个任务。重试不会重复创建，改变同一请求的目标、来源、验收或项目返回 409。

**新任务保持 `pending`，不发布执行开始记录。** 此接口不调用模型、不生成分工、不启动后台活动，不接受 `run` 或 `continue`。需要执行时，使用既有任务接口单独分工与推进；不要重试创建来恢复结果不明的执行。

新建另一项工作不暂停、重置或重新验收原任务。任务详情、工作项、成果与验收继续使用 `/api/tasks/{task_id}`。

## 历史记录

- `GET /api/rooms`：读取群列表与各群任务 ID，不隐式迁移或写入记录。
- `GET /api/rooms/{room_id}`：读取单个群。
- `POST /api/rooms/{room_id}/tasks`，正文 `{"task_id":"已有任务 ID"}`：将尚未归群的任务关联到本群。重复关联本群是无操作；已属于另一群则返回 409。当前不提供移群操作。
- `POST /api/rooms/import-legacy`，正文 `{}`：显式将未归群的历史任务逐项映射为独立群，不自动合并任务。重复调用可恢复未完成的导入，不重复已完成部分，不改写历史事件或哈希。

## 读取过程

`GET /api/rooms/{room_id}/events?limit=100` 按事件序号返回本群消息和关联任务的原始过程记录，不复制任务输出。结果包含 `events`、`next_after_seq`、`membership_seq` 与 `has_more`。分页大小为 1 到 200。

继续读取时带上上次结果：

```text
GET /api/rooms/{room_id}/events?after_seq=123&membership_seq=100&limit=100
```

如果关联任务发生变化，旧游标返回 409，客户端应清空该群的分页缓存，从头刷新。这样新加入的任务即使历史早于原游标，也不会漏掉。空页保留游标；事件序号是全局序号，允许不连续。

## 上下文与权限

通过本接口创建的新任务默认使用本任务的内容上下文，不会因为同群、同项目或使用同一角色，就自动读取其他任务的成果与角色经历。角色配置和明确采用的通用/项目规则仍适用。需要沿用指定来源材料时，现有衍生任务接口仍可使用，不自动把整个群历史作为当前执行要求。

新任务的 CLI 调用使用独立进程，调用后关闭，防止复用进程内的隐式历史。这不限制自定义 CLI 的磁盘缓存、远端会话、文件访问或联网能力，也不是操作系统沙箱。仅将旧任务关联进群不会改变其历史上下文策略或在途执行行为。

接口沿用工作台访问令牌、同源写入和请求体大小限制。当前没有每群独立账号或 ACL；拥有工作台访问权限的人可以访问这些群与任务。
