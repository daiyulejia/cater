# 暂停与故障恢复

## 暂停、恢复和取消

任务菜单支持暂停、恢复及取消；在群里明确提出相同要求，也可由对话模型识别为控制动作。问题、进度追问和讲解仍可继续。程序不以某个固定词自动改变执行状态。

- 暂停：持久保存状态，不再启动后续工作、复核或检查。已经发出的调用可能仍返回，成果与回执保留，不承诺立即终止外部进程。
- 恢复：从当前有效计划和提交继续。不会重新生成已提交内容，也不能绕过未核对的未知调用。
- 取消：当前任务不再执行；已有记录可读。继续新的工作需要新任务，不能用普通“继续”撤销取消。

HTTP 接口为 `POST /api/tasks/TASK_ID/control`，请求为 `{"action":"pause","request_id":"control-request-001"}`。动作支持 `pause`、`resume`、`cancel`。重发同一操作使用原请求标识；改变动作必须换标识。控制状态在任务详情的 `execution_control` 中返回，不改变需求版本。

暂停前排队的执行请求不会在恢复后自动复活。工作台 JSON 新建入口将任务、需求登记和首次执行意图在同一事务保存；重启可以恢复尚未启动的首次执行，但必须仍与原要求、控制状态和授权一致。已启动的活动使用进程持有的内核锁核对存活：仍在执行的活动及其排队续跑不被另一个恢复进程判死；父子活动交接时先保留子活动所有权。执行进程消失则留下中断记录，不盲目重放。完成与失败只能登记一个终态。

## 卡住时如何判断

先看具体检查点与失败原因，而不是把所有停止都理解成“没有放行”：

| 情况 | 当前行为 |
| --- | --- |
| 阶段复核指出有正文依据的缺陷 | 内置纯文本 API 执行者可连续修正并独立复核，每项每轮最多三次修正。相同正文再次卡在相同标准，或循环回到已有失败版本时，停止原地重试并保留检查点；后续可从这里继续，不重做已验收的上游。 |
| 浏览器测试方案错误或明确漏测 | 复核人可明确提出修正检查；在同一份成果上更正方案、实际重跑并再次独立复核，然后继续交接。不会把失败回执改写成通过，也不因测试问题要求作者重写程序。 |
| 同一验收目标的成果更新 | 可以复用先前通过的检查步骤，但必须在当前版本重新执行、取得新回执并重新复核，不复用旧的通过结论。 |
| 整体复核指出有正文依据的具体缺陷 | 同一授权执行轮可将受影响成果及其依赖交回修正一次，再逐项复核和整体验收。已在本轮阶段返工的受影响项不再进入整体返工波次；整体返工项不继续触发阶段自动修正。要求变化、未知结果、依据不足或不可信执行器不会借此自动重试。 |
| 复核格式错误或证据不足 | 不伪装通过，也不因此重新生成成果。整体复核仅对可信纯文本 JSON 语法错误允许一次格式纠正，同一认领下保留原标量值和结构；无法保留原判断、大小超限、证据或语义错误都不借格式修复重答。 |
| 内置纯文本 API 限流、传输失败或暂时性 HTTP 408/500/502/503/504 | 网页任务默认等待后自动续试一次，保留原失败与恢复记录，不必先发送“继续”。仍失败则保留检查点，远端是否已计费仍未知。带工具的调用不继承这一恢复保证。 |
| 规划或整体复核留下过期纯文本调用 | 仅依据调用开始时保存的可信执行契约关闭旧认领。关闭本身不调用模型，后续明确继续才重评，迟到结果不能放行。 |
| CLI、自定义执行器或旧记录结果不明 | 不能仅凭超时判定已停止、没有副作用；需要可信操作者核对后再继续。 |
| 排队请求的前序活动失败 | 排队请求保留关联失败终态，不会默默消失，也不会借失败自动重放未知调用。 |
| 讲解原回答合法，但引文未匹配来源 | 可信纯文本通道在同一提问认领内最多纠正一次引用；保持回答、判断、边界和已核实引用不变，两次用量分别记账。仍无法核对就明确失败，不把重新编造答案当作修复。 |

规划、阶段复核和整体复核都有持久认领。相同输入的并发请求不能重复取得复核所有权；新请求也不能把旧调用的迟到回复当作新结论。需要人工核对时，运行时提供可信本地接口：`planner.reconcile` 与 `delivery.reconcile` 核对调用哈希、当前版本、证据事件及停止/副作用声明；`work.reconcile_review` 绑定阶段复核认领并要求操作者确认调用已停止、记录核对依据。它们不提供模型自我解锁。具体参数以方法签名为准。

## 自动续试的边界

原生 API 工具调用的新失败记录会按已知信息保留 HTTP 状态码、连接/超时类别与失败发生阶段，提示使用中文；不保存供应商错误正文或凭据，也不把 HTTP 402 一概解释成余额不足。只有旧的 `DriverUnavailable` 类型时，具体原因仍是未知，不事后补猜。请求阶段失败也不证明远端未处理或未计费；这些诊断信息不授权自动重试。

原生消息协作另有本地事件结算保护：七类纯本地工具的动作事件与结束回执在同一事务提交，调用开始记录保留独立的版本化契约。若在回执写入前崩溃，未提交的本地动作会回滚；在确认原运行结束前仍显示未结算，不提前断言没有发生。文件落盘和外部命令不进入这个事务，失败或超时不能冒充无副作用，也不把旧日志事后升级为新保证。

### 原生团队的进程中断

新启动的原生运行会记录版本化的恢复契约，以及当时的目标、控制、规则、模型配置和工作目录范围。服务启动时用内核锁核实原消费者已经消失，才原子登记中断和一条给店长的恢复通知。通知持久保存；若已入队但尚未认领时再次重启，可恢复同一队列，不重复派一份工作。仍持锁的消费者不会被判死。

恢复从新的模型调用开始，店长读取当前工作检查点、实际成果和回执，再判断如何继续，不重领原消息或回放旧工具请求，也不持久化供应商的私有思考。`read_checkpoint` 可分页读取尚未交还的原委托；`send_message.continue_assignment_seq` 让原发件人明确补充原委托，接收者仍向原委托人交还，而不是收到另一份重复工作。角色失败或中断后的反馈不关闭原委托。运行终态和自动交接消息也在同一本地事务结算，避免“运行结束但回报丢失”。

顾客已发来新消息时，优先由新消息理解上下文，不额外添加孤儿运行恢复通知。暂停、取消、换目标、变更规则/模型配置或工作目录后，旧范围的恢复通知不会自动执行；先暂停再恢复也不使旧通知复活。恢复通知本身已被认领后再中断，不会无限生成恢复通知或连续重试模型。接入失败仍保留明确失败记录，需要新的有效输入或控制操作继续核对。

未正式交回的失败/中断工作、未闭环复核，以及发布成果或工作目录操作的未知影响，不能被恢复流程算作最终完成。工作目录未知调用沿用 `runtime.workspaces.reconcile(...)` 的可信本地核对接口；成果发布未知调用另有 `runtime.team.recovery.reconcile_publication(task_id, started_seq, reason=..., invocation_stopped=True)`。操作者须先实际核对成果记录及本地文件，并确认原执行已停止；接口绑定原调用哈希与身份，不改写原始回执，也不提供模型自行解锁工具。核对后仍应先读取当前文件，不重放原操作。

这些是恢复调度与事实完整性的保证，不代表模型一定会选对下一步，也不证明任意长任务都能自动完成。旧的无恢复契约运行仍只保留中断记录，不自动补发；真实任务的恢复质量和成本需单独验证。

原生静态网页检查另有版本化进程清理契约：收到宿主确认的进程树结束及输出关闭后，即使该次超时也只保留检查失败，不永久占用待核对状态；不会自动重放旧检查。没有回执、旧契约或清理未确认的浏览器调用仍需核对，未核对前不重复启动检查或结束交付。可信本地操作者可在确认旧进程停止后使用 `runtime.team.recovery.reconcile_browser_check(task_id, started_seq, reason=..., invocation_stopped=True)`；它绑定原调用哈希，不把旧检查改成通过，不提供模型自我解锁工具。常规断言失败不需要人工解除。

网页任务默认只对仍有有效认领的内置纯文本 API 请求续试一次，覆盖规划、成果生成、阶段复核、浏览器检查规划及最终复核。默认等待5秒，并尊重服务商合法的 `Retry-After`；要求等待超过120秒或认领剩余时间不足时，不提前重试。永久鉴权错误、不完整响应、未知异常、CLI、自定义驱动和带工作目录工具的执行不会进入这条路径。聊天理解与讲解调用目前也未开启自动续试。

等待不持有数据库写锁，仍可聊天、改方向或暂停。发出续试前会重新核对要求、认领、控制状态、接入配置、实际凭据、预算和熔断状态；出现新的工具执行或文件采集记录，也不能沿用旧上下文。关闭再恢复任务不会让旧等待自动复活。两次失败不会继续空转；恢复成功只表示连接请求返回，成果仍需实际检查与验收。

聊天中的轻量系统记录会从等待更新为已恢复、失败或取消，原始错误保留在展开详情。服务进程中断后，确认原活动已结束才取消对应的等待记录，不把重启当作重放旧调用的许可，也不把未结束的工具执行伪装为已核对。

可通过 `cater web --no-text-retry` 关闭网页自动续试。直接使用 Python `Runtime` 时默认仍是一次调用，需显式传入 `text_retry=True` 开启上述策略。`--driver-attempts` 仍保留兼容，但不会给 CLI 或任意执行器增加隐式次数。CLI 存活探针可以为后续新请求重建进程，不代表旧请求幂等；第三方 CLI 自身的内部行为不受此保证覆盖。

## 网络中断和升级

普通刷新会在同一标签页的 `sessionStorage` 记住当前对话位置，明确选择的新建页也会保留。这个小记录只有版本、访问身份的 SHA-256 绑定和对话 ID，不含聊天、标题、草稿或访问凭据，也不是加密存储或权限边界。位置须在当前任务列表中核对；原群不可用、记录变化或身份不匹配时会提示手动选择，不静默切换到别的群。恢复位置不会发送消息、恢复暂停或启动任务；等待期间用户的新选择和新输入优先。

网页读取与写入都有超时提示。写入超时不代表服务器没有收到；新建任务在当前浏览器会话暂存原请求标识与内容，刷新后可恢复待确认输入，使用同一标识重试，不重复创建或执行。不会自动重发。暂存最长保留24小时，并绑定当前访问身份；身份变化、损坏或过期时丢弃，存储不可用时说明刷新恢复受限。

延迟加载的界面模块失败时，局部显示“这部分暂时打不开”，不因此宣称后台任务停止。点击“保留草稿并刷新”会先在当前标签页的 `sessionStorage` 保存各对话草稿、当前对话及追问/衍生模式，保留一小时；它不是跨设备记忆，也不是加密存储。存储不可用、身份变化或输入已变化时不贸然刷新。平时未发送草稿仍在内存中，不能据此保证手动关页、浏览器崩溃后恢复。

普通聊天、旧式成果追问和衍生任务的提交结果未知时，这个显式刷新入口也保留原请求编号；恢复只填回输入，不自动发送。残缺或对话不匹配的成功响应不清空原请求。正在提交、问题卡有未提交选择/填写或尚未确认的提交时，会阻止刷新并保留页面；空白默认项、已回答及已过期的问题卡不会永久阻挡。其他写操作需按具体接口判断，不能将这些入口的幂等性推广到全部操作。

前端构建使用 `scripts/build_web.ps1`：先在独立暂存目录构建，再替换包内页面，发布失败尽量回滚旧目录；不覆盖开发用的 `web/dist`。网页服务优先使用包内页面，启动时捕获有界只读资源快照并核对 `workroom-manifest.json` 的入口及静态/动态依赖，缺件则启动失败，不拼凑两个版本；运行中的服务继续返回它启动时的资源。清单不作为公开资源返回。自定义包含脚本或样式的静态包也需要同格式清单。运行时动态拼接、未写入清单的资源不在静态完整性保证范围内，仍需浏览器实测。

计划现在绑定角色、模型通道和浏览器执行器指纹。升级前缺少该指纹的旧计划，或更换角色/执行后端后的计划，需要重新规划和验收；历史成果保留为候选，不回写旧验收。仅调整超时与预算不改变该指纹。

默认演示可以将原示例计划重新绑定到新范围，但明确标记为示例复用，不声称理解了新要求。真实执行者没有规划模型时会说明缺少能力，可配置规划通道或通过 `Runtime.plan_work` 安装新计划，不会永久显示正在规划。

这些机制约束版本、调用所有权和已知副作用，不证明模型判断正确，也不是通用宿主机沙箱。真实工程操作、长期成功率与恢复后的语义质量仍需单独验证。
