# 从已有对话开展另一项工作

本页介绍已有网页中的任务背景快照。一个群承载多项工作的独立后端接口见 [长期群聊接口](rooms.zh-CN.md)，尚未替换现有网页入口。

在对话工具栏选择“基于此对话开新任务”，再用聊天框发送新目标。原任务可以继续运行；新任务有自己的目标、分工和验收。取消创建不会删除原对话的未发送草稿。

新对话工具栏的“来源”可以查看创建时取得的材料，并回到原对话。返回原对话只切换页面，不更新新对话的背景。

## 继承的内容

- 创建时的来源目标和顾客要求，保留任务 ID 与事件序号。
- 最多三份近期可用成果，保留文本正文或工程 ZIP 的确切版本引用，以及来源和当时的验证状态。工作项成果必须在创建时阶段验收有效；历史无工作项的成果标为未验证。
- 当时已采用的任务专属店规，复制为新任务可独立修改的店规。

不会复制计划、在途调用、完成状态或验收凭证。旧成果即便曾通过检查，也要按新目标独立验收。角色身份沿用配置；新群不会读取旧群后来的发言或角色活动摘要。

真实模型的消息协作会收到冻结背景的有限索引，并可按需读取当时保存的来源目标、顾客原话和成果正文。长正文分页读取，不在每次调用中重复附上全部旧材料；未保存或超出捕获范围的内容会明确说明，不能查询原群实时内容来补齐。来源群采用过的新目标也会在创建时记录，但这些材料只是历史参考，不自动成为新群目标、权限或验收结论。

背景总量有上限：最多 256 条要求、256 KiB 的序列化背景，成果最多三份。过大的要求会拒绝创建，避免默默丢掉约束；未复制的成果数量会显示。后续再次从新群衍生时，背景按原来源去重，不无限嵌套聊天记录。

### 工程文件

继承工程 ZIP 时，背景只保存冻结引用，不复制整包源码。角色先用 `read_background` 的 `section: "artifact"` 和 `artifact_seq` 读取当时的文件清单，再加 `path` 读取其中的文件。文本使用 `offset`、`limit` 按 Unicode 码点分页，默认从 0 起返回最多 8000 字符，每页最多 16000；清单本身不接受这两个分页参数。二进制仅核对字节与摘要，不解释图片或执行程序。

读取只解析被冻结引用指向的那条不可变发布记录和数据库中保存的 ZIP，不能按文件名取原群新版，也不读取原工作目录。原群继续修改或再次衍生都不会改变这个版本；旧快照若已有完整的版本引用，也可读取相同的原发布记录，不改写旧快照。缺少引用、归档字节或校验不一致时明确返回不可读，不自动换用其他版本。

工程包仍需要完整的 SQLite 数据库备份；单独导出背景 JSON 或事件 JSON 不包含 ZIP 字节。历史清单可读不等于成员已读，读取成功不等于复核通过，也不会给新群授予父群工作目录权限。

## 创建之后

原群的消息、目标修改、成果返工和任务店规修改不会自动更新新群；新群的新发言与成果也不会自动回流到原群的共享记忆。两个群分别积累自己的事件。当前不提供自动同步或手动导入后续版本的按钮。

明确发布的猫咖通用店规、所属项目店规仍按原有作用域适用。它们是独立的规则管理操作，不是原群普通聊天的自动传播。

## API

`POST /api/tasks/{source_task_id}/derive` 接收：

```json
{
  "goal": "根据已有网页方案，另写一份使用指南",
  "request_id": "unique-request-20261015",
  "run": true,
  "background": true
}
```

`request_id` 对同一次发送保持不变。网络失败后以同样内容重试会返回同一个任务，且不会重复启动协作；同一标识更换目标或来源返回 409。创建返回标准任务详情，附带 `background`。背景与项目由服务器从来源任务读取，不能由客户端注入。`run: true` 总是后台执行。

背景与新任务的创建写入同一个事件，并以日志头检查保证读取期间发生变化时重新取快照。服务若在创建后、启动前中断，已建任务仍可读取；需要在该任务继续协作，不通过创建重试盲目重放调用。

衍生任务的 CLI 调用使用独立、调用结束即关闭的进程，输入由事件记录和固定背景重新组装，避免复用原群进程内的隐式历史。普通任务的长驻进程不受影响；代价是衍生调用会有额外启动开销。

这保证 Cater 组装的上下文独立，不等于文件系统隔离。自定义 CLI 或远程服务仍应按请求的 `context.task_id` 隔离磁盘缓存和远端会话；执行工具须单独管理工作目录、权限和副作用。
