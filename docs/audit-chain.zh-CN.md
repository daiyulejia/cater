# 事件链与签名校验

事件链核对记录内容和前后关系。可选 HMAC 还核对签名所用密钥；它不证明成员结论正确、测试充分，或主机权限已经隔离。

未配置审计密钥时，纯哈希日志按既有方式读取和校验。配置 `CATER_AUDIT_KEY`、`--audit-key-file` 或运行时 `audit_key` 后，新事件签名；需要验证旧密钥的记录时，提供对应的 keyring。不要把密钥写进聊天或提交到仓库。

```powershell
python -m cater --db .cater/cater.db chain
python -m cater --db .cater/cater.db --audit-key-file C:/private/cater-audit.key chain
```

当前校验策略：

- 显式空密钥是配置错误；只有未提供密钥才表示未启用。
- 可以有启用签名前的未签名前缀。签名事件通过前一条哈希锚定此前内容，但不能证明启用签名前内容从未被改写。
- 出现第一条签名后，不接受无签名的后续事件，防止清除后缀签名再重算公开哈希来降级校验。
- 提供验证密钥的非空日志，如果完全没有签名，会报告失败。空日志没有待验证记录。
- 保留原有签名算法与历史记录，支持旧密钥和新密钥共同核验；不为修复报告重写事件。

这会收紧历史兼容：曾在签名历史后用无密钥程序追加记录的库，现在不会报告完整校验通过；给完全未签名的旧库只提供密钥，也不会凭空变成已认证历史。应核对原始记录与备份，不能以删除历史或伪造签名修复提示。

事件链不能单独发现完整尾部被删除或整份数据库被旧备份替换；需要独立保存可信链头或外部检查点。SQLite 的追加触发器也不能代替数据库文件权限管理。
