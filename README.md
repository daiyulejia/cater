# Cater

中文 | [English](README.en.md)

**一间在对话中协作的 AI 猫咖。**

告诉店长你想做什么，和伙伴们一起推进任务。你可以随时补充要求、`@` 某位伙伴，查看协作记录和成果，不必在聊天与任务表单之间来回切换。

Cater 正在开发中，已接入模型工具调用、工程文件操作、命令执行与多角色交接、版本复核。**快速开始默认运行本地演示，不调用真实模型，也不会替你修改工程文件或完成工程任务。** 实际执行需要配置支持工具调用的模型通道并授权工作目录。

## 快速开始

需要 Python 3.11+。在源码目录运行即可，无需安装 Python 第三方运行依赖；仓库已包含构建好的网页。

```bash
git clone https://github.com/daiyulejia/cater.git
cd cater
python -m cater --db .cater/cater.db web --port 8766
```

打开 [本地工作台](http://127.0.0.1:8766/)。任务记录保存在当前目录下的 `.cater/cater.db`；日常使用请固定同一数据库和端口。从其他目录启动时，`--db` 使用原数据库的绝对路径。

已有源码时，只需执行最后一条命令。修改前端才需要 Node.js 和 pnpm，见 [前端开发](web/README.md)。

端口已占用时，先确认是否已有 Cater 在运行。更新源码不会更新已运行的服务；升级时应先确认任务空闲、备份数据库，再停止原服务并用同一命令启动。使用 `--no-startup-recovery` 可关闭启动时自动续接，随后由你在对话中继续工作。另开端口适合隔离测试，并不会升级原入口。

## 在对话里工作

1. 直接发送目标，例如“帮我设计一个个人作品集网页”，也可以写“`@罐头` 先看看页面布局”。
2. 查看伙伴的分工与回复，继续在同一对话里补充要求或调整方向。
3. 在聊天或成果板中打开已发布的成果，查看诊断、交接说明和过程回放。

当前可用：

- **对话协作**：发起任务、点名伙伴、追加方向，让伙伴委托工作、交回结果，并查看进展。
- **衍生对话**：带上已有对话的背景快照，独立开展另一项工作，原群照常推进。
- **成果阅读**：打开、复制或下载伙伴发布的文本、Markdown 和代码正文，也可发布真实工程文件与工程 ZIP 快照。
- **工程工具**：绑定工作目录后，按授权读取、搜索、创建和修改文件，运行预配置命令；可对已发布成果的确切版本副本运行检查。
- **过程核对**：查看子任务依赖图与协作回放，区分成员自述和实际检查记录。
- **版本复核与交付**：可发起独立复核、修订后复核；正式交付核对获批版本及尚未交回的工作，交接说明可保留实际命令回执与复查步骤。另有工作项依赖调度及阶段、整体验收流程。
- **可配置伙伴**：调整角色名称、职责和模型通道；支持本地 CLI 与兼容 Chat Completions 的 API。

## 接入真实模型

先体验演示，再按 [接入示例](examples/README.md) 配置自己的模型或本地 CLI。多个角色可以共享一个通道，也可以分别配置。

内置 Anthropic Messages 与兼容 Chat Completions 的驱动已接入原生工具回合，可执行模型发出的工具请求。按[工程工作目录与工具](docs/workspaces.zh-CN.md)配置并绑定目录，以 `read_only`、`edit` 或 `execute` 授权文件和命令能力；仅配置模型凭据不会自动授予工程权限。本地 CLI 的执行能力取决于对应驱动与配置。

API 密钥放在环境变量中，不要写进角色卡、聊天或提交到仓库。

## 当前边界

- 已有工具执行、交接和版本复核机制，不等于已证明真实模型能稳定完成长任务或高质量自治工作，也不保证任意任务可完成。模型的结论、复核通过或命令成功退出，仍须结合实际检查范围判断。
- 已有中断续接、未知影响阻断与人工核对入口。命令或发布结果未知时，须先确认执行已停止并核对实际影响，不自动重放；这不代表任意中断都能自动恢复或保证交付正确。
- Cater 目前不提供通用文件或网络权限沙箱。角色设定、提示词和进程管理不能替代权限隔离；只运行可信的驱动配置与命令。
- 工作台默认仅监听本机。远程访问需要显式启用、设置访问令牌，并自行提供 HTTPS 或等效受控网络边界。
