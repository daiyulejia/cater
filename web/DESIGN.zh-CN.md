# Cater 工作间：界面设计基线

## 本轮：任务本里找旧对话

任务增多后，侧栏需要承担查找而不是让顾客逐项翻阅。桌面在任务本标题下放一行标题搜索与“全部 / 未完成 / 已完成”分段筛选；只搜索任务标题和编号，不暗示已搜索聊天正文。手机默认仍只有横向任务列表，放大镜按需展开查找，收起任务本时一起隐藏。

筛选仅改变列表，不切换当前对话、不改变执行、不删除任务、不清空任何草稿。已完成依据任务的 `done` 状态，正在执行的新一轮仍归未完成，不把单次协作结束当作整件事完成。无匹配与没有任务分别呈现，并提供恢复全部的入口；清除搜索只清空关键词。匹配数保持轻量，任务按钮限制宽度，长中文和长编号不撑开页面。

验收包括中文与英文大小写、编号搜索、状态与关键词组合、已完成任务的新一轮执行、无匹配恢复、筛选隐藏当前任务后继续编辑、手机按需展开与收起，以及桌面/平板/手机聊天区域不被挤掉。

## 本轮：今天在店里的伙伴页

聊天保留轻量“今天在店里”入口，打开二级伙伴页查看猫咪和其他伙伴的头像、名字与状态。桌面为宽幅独立页面层，手机占满视口；不切换任务，返回时草稿保留。头像作为主视觉，状态和原因分层显示，不展示内部职位、密钥或地址。

“全员营业”仅用于所有成员有可用依据的情况；演示明确写“演示营业”。没有近期真实调用证据写“待确认”，不主动消耗模型额度做检查。缺少凭据、Cater 预算耗尽、近期调用失败或熔断时显示“休假”和具体原因；不猜订阅余额。刷新只重新读取本地状态，最新成功观察五分钟后过期，服务重启也回到待确认。

伙伴页仍可点名回到当前聊天；点名不等于授权、发送或安排执行。聊天页的成员席和任务本收起机制保持不变。

营业摘要必须覆盖当前名单中的每位伙伴：新增成员缺少状态时回到待确认；重复或已经离店的状态不计入人数。未知状态不能被演示状态掩盖，局部成功不能代表全员可用。

## 本轮：电脑常驻，手机让出聊天空间

电脑端保留任务本、聊天和成果侧栏，是主要工作画面。手机和平板默认展示任务列表与成员席，但分别提供可逆的收起按钮；收起任务列表仍保留当前任务入口和新建按钮，收起成员席仍保留伙伴入口。只改变可见性，不切换任务、不清空草稿、不影响团队执行。切回电脑始终展示这两栏，不继承手机收起状态。

权限与沙箱配置另行按执行边界设计，不能用视觉开关伪装权限已经受限，也不因打开电脑网页就授予主机访问。

## 本轮：在输入框里找伙伴

直接输入 `@` 时，在输入框上方打开成员建议；中文名字过滤，头像和姓名保持与成员席一致。建议框固定宽度并独立滚动，不挤高聊天、不遮住发送按钮，手机可触摸选择。上/下箭头选人，普通 Enter 只确认点名，Esc 收起；Ctrl/Command+Enter 保留显式发送语义。

选择替换光标前的点名片段，保留光标后的正文，并补齐后端识别需要的分隔。邮件地址不触发点名，选中一段文字时不替用户覆盖。输入法组合期间不截获 Enter 或发送快捷键。失焦、切换任务和完成选择后关闭建议，不发送请求。空匹配时显示轻量“没有匹配的伙伴”，不猜测角色身份。

验收包括中文输入法、键盘选择、手机触摸、正文中间补全、邮件地址、无匹配、任务草稿隔离与发送次数；先设计再实现，最后检查实际页面。

## 本轮：成果板的返回路径

手机成果板不是新页面，而是聊天旁的一张记事板。打开时聚焦面板，背景聊天不可操作；Esc 或关闭按钮返回原入口，草稿和消息位置不变。成果正文可在记事板上继续打开，先关闭正文回到记事板，再关闭记事板回到聊天。

桌面仍使用常驻侧栏，不套弹窗。视口切到桌面时关闭移动弹层，避免隐藏遮罩继续锁住聊天。标题和关闭按钮固定，只有内容滚动；使用既有深绿标题带和暖白阅读面，不另加装饰卡片。验证键盘焦点、嵌套阅读、任务切换、手机与桌面来回切换。

## 本轮：把伙伴带回聊天桌

设计先行：当前聊天页的头像只在桌面侧栏静态展示，手机无法点名伙伴；共享记忆在成果板顶部铺开，挤走当前成果。保持聊天主入口，不增加新的导航页。

- 聊天标题下设置一条横向成员席，展示所有伙伴的头像和名字。点名只追加到当前任务草稿并聚焦输入框，不发送、不改变任务、不宣称成员在线。手机保留同一入口，成员席独立横向滚动。
- 成员按钮保持固定高度，暖白底与淡蓝边框；珊瑚色用于悬停和聚焦，不把整页涂成奶油色。消息区域改为微凉的柔白，侧栏和输入区保留温度，让头像与正文更突出。
- 成果板使用清楚的深绿标题带，当前成果与参与情况优先，共享记忆移到底部的折叠区域。折叠只影响呈现，不删除记忆，也不改变模型上下文。
- 新入口须覆盖草稿保留、只点名不发送、任务切换隔离和键盘焦点；检查手机 390px、平板 768px、桌面 1365px 的聊天高度、长名字与横向溢出。

## 核心体验

用户不是在操作一张多 Agent 流程图，而是在同一间猫咖里和伙伴交谈、看他们接力、取回成果。聊天是第一视线；组织结构和审计能力存在，但不抢走对话的位置。演示模式必须明示，不能让静态脚本看起来像已完成真实执行。

## 两个画面

- **还没开始聊：** 店内场景与四只猫是情绪锚点，店长开口邀请；任务示例只填入输入框，不替用户发送。左侧展现成员，不摆空白任务架。输入框在手机首屏可见。
- **正在聊：** 左侧是任务本，中间是消息和始终可触及的输入框，右侧是成果、交接和本机检查。手机上先看聊天，成果以独立抽屉打开，不能把输入框挤到页面底下。

## 视觉语言

- 日光珊瑚色负责温度和主要操作；鼠尾草绿负责团队与过程；淡蓝色负责信息层次；深绿墨色承担正文。不要把全页涂成一种米色、绿色或棕色。
- 门头条纹只在顶边出现一次。脚印用于任务本和发送；审计保留盾牌，成果保留咖啡杯。物件必须能说明当前位置或操作，不把爪印撒在每个模块。
- 猫咪是最先看到的角色。四只猫与店长、白露、阿程、知夏各有可辨认的头像。人物插画与场景统一色温；所有图片检查解剖、裁切和小尺寸辨识度。
- 对话气泡有适度体积和角色色线，系统判断与成员发言不混作同一白框。标签嵌在消息层级里，不把标题、状态、审计号都做成飘在文字外的胶囊。
- 可点的示例像便签，成果像记事板；不使用卡片套卡片。圆角不超过 8px，装饰必须让内容更好读。

## 交互边界

- 点猫咪会把 `@名字` 填到输入框；不会擅自发送或启动工作。
- 任务示例也只填入输入框。发送按钮是猫爪，但悬停说明与无障碍名称必须明确写“发送”。
- 本机检查结果和成员自报分开；命令通过仅代表该命令在当时退出成功。
- 移动端长对话只在对话区域滚动，输入框留在视口内。切换任务与成果抽屉后不丢草稿。

## 每轮验收

先看 390px 手机、768px 平板、1365px 桌面实图，再确认头像、图片裁切、输入框、成果抽屉、长中文和错误提示不重叠；示例、点名、发送与审计按钮至少各走一遍。最后运行前端 lint/build 与仓库全量测试。新增元素必须能解释它在画面中的职责，否则移除。

## 本轮：任务切换与消息归属

设计动机：顾客可以在几个任务间来回说话。聊天区、成果板和发送目标必须始终属于同一件事，慢响应不能改变顾客当前看的任务。

- 选择任务后，标题立即对应所选任务。详情等待区使用店长头像、轻量加载标记和“正在接上这段对话”；暂时收起旧消息与旧成果。加载成功后才能发送，失败时在同一区域给出重试入口。
- 新任务和每个已有任务各自保留一份内存草稿；切换时恢复对应内容。任务列表用小便签图标提示有未发送内容，避免额外弹窗。草稿不写入浏览器存储或事件链。
- 发送中的猫爪按钮保留尺寸，用小型加载图标表示等待。输入框继续可编辑；响应只清除仍与本次发送一致的内容，后续输入保留。重复点击或快捷键不会重复发送。
- 发送后切换任务，仍停留在用户选定的任务；完成结果更新原任务。错误也留在对应任务，不能跑到另一个聊天里。
- 当前对话的刷新串行进行。正在协作时更频繁，空闲时放缓；页面隐藏时暂停自动刷新，重新显示时立即核对，避免慢网络造成请求堆积。
- 进入任务或切换筛选时定位到最新消息。停在底部时跟随新增消息；向上阅读历史时保持位置，用带向下箭头的小按钮提示“查看新消息”，不遮挡输入框。点击后返回底部并恢复跟随。

验收重点：用延迟响应验证 A/B 任务切换、各自草稿、发送期间追加内容、重复发送、发送后进入新对话；再检查桌面和手机等待状态的布局与输入框位置。

## 本轮：成果阅读与带走

设计动机：一段“已经完成”的摘要不能替代可阅读的成果。顾客应在聊天里打开伙伴发布的正文，理解后带走，关闭阅读器时仍回到原任务和草稿。

- 聊天里的成果消息和右侧成果板共用“查看正文”入口。有摘要但没有正文的历史记录保持摘要展示，不制造空文档；只有路径时显示资源引用。
- 阅读器像工作间里铺开的笔记纸：桌面从右侧展开，宽度最多 900px；手机使用完整视口。暖白正文、珊瑚色顶边、深绿标题和简洁分隔线，正文不再套卡片。长标题换行，代码和表格在自己的区域横向滚动。
- 顶部固定成果名、发布者和来源。演示内容使用“演示样例”，外部驱动输出使用“成员发布”，不把发布等同于验证。复制、下载和关闭使用带说明的图标，操作反馈留在工具栏内。
- Radix Dialog 负责焦点约束、Esc 关闭和屏幕阅读器语义。关闭后恢复到打开成果的入口，原聊天位置和草稿保留。
- Markdown 使用成熟解析器；不执行 HTML，不自动加载外部图片。代码始终作为文本展示。外部来源仅允许明确的 HTTP/HTTPS 链接；本地路径、可执行 URL 和带凭据的 URL 保持不可点击。
- 正文限 64 KiB UTF-8，每次贡献最多八项成果。超限或格式不合法时保留摘要并说明正文不可用，不悄悄截断可执行代码。下载只生成这份正文，不访问引用路径。

验收重点：从聊天和成果板打开同一正文、复制与下载内容、关闭后保留草稿、Markdown/代码/长中文的桌面与手机布局、旧摘要兼容、恶意 HTML/图片/链接、超大正文，以及真实 adapter 的字段合同。
